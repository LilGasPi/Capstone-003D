# Retrospectivas — Estacionando

## Retrospectiva de la iteración previa a la semana del 5 de octubre

Esta retrospectiva se documenta a partir del trabajo realizado, la presentación anterior y el feedback explícito recibido de la profesora.

### Qué funcionó bien

- Se logró mostrar una propuesta de producto coherente y visualmente consistente.
- El equipo dispone de una aplicación web con varios flujos navegables.
- Se construyeron procesos de reserva, publicación y pricing/ruteo como base conceptual.
- Existe material técnico, código y evidencia distribuida en repositorios.
- El equipo pudo realizar una demo y explicar el problema/solución.

### Qué no funcionó bien

- La metodología no estaba suficientemente documentada en Git.
- Faltaban artefactos explícitos: Product Vision, Product Backlog, Sprint Backlog, DoD y retrospectivas.
- Los BPMN fueron percibidos como diagramas de flujo realizados en Bizagi, no como modelos BPMN completos.
- Hubo problemas de notación BPMN: gateways poco claros/desconectados, conectores que cruzan compuertas y poco uso de tipos de tarea/eventos/subprocesos.
- La presentación podía mezclar visión futura con estado actual del software.
- Faltó una trazabilidad directa entre requerimientos, evidencia y estado.

### Causas identificadas

1. Se priorizó demasiado la construcción visual y funcional sobre la evidencia metodológica.
2. Los BPMN se diseñaron desde la lógica del flujo antes que desde la semántica BPMN.
3. No existía una Definition of Done formal para impedir marcar como terminado trabajo parcial.
4. La documentación estaba distribuida entre Drive, repositorios y presentación.
5. No se había establecido una matriz única de avance y roadmap.

## Start / Stop / Continue

### Start
- Vincular cada entrega a evidencias concretas.
- Revisar DoD antes de cerrar historias.
- Usar tipos BPMN correctos: User Task, Service Task, eventos, pools y gateways.
- Registrar decisiones metodológicas en Git.

### Stop
- Presentar prototipos o pantallas como funciones completas sin validación.
- Dibujar conectores BPMN largos que atraviesen compuertas o actividades.
- Depender de documentación dispersa sin índice.

### Continue
- Mantener una identidad visual coherente.
- Trabajar con demo funcional.
- Refinar el producto según feedback docente.
- Mantener el foco en los dos usuarios principales: conductor y anfitrión.
